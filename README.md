# Puro — puropesu.fi

Сайт выездной химчистки мягкой мебели и матрасов (Хельсинки и столичный регион): онлайн-запись с реальными свободными слотами, прайс из базы, три языка (fi без префикса, `/ru`, `/en`), блог, админка.

**Стек:** Next.js 16 (App Router, Server Components, Server Actions) · TypeScript · Tailwind CSS v4 · next-intl · Supabase (Postgres + RLS + Auth + Storage) · Zod + react-hook-form · почта по SMTP (nodemailer) · Playwright / Vitest.

Сторонних сервисов в записи нет: брони, слоты, скидки, фото и заявки живут в вашей базе Supabase, письма уходят через ваш SMTP-сервер. Защита форм — honeypot и лимит запросов по IP в той же базе (без капчи и вебхуков). Google Tag Manager подключается, если задан `NEXT_PUBLIC_GTM_ID`; теги внутри контейнера подчиняются Consent Mode v2 (по умолчанию согласие «denied», обновляется из баннера cookies). Прямое подключение Google Analytics / Ads через gtag.js — только если вы зададите их ID, и только после согласия посетителя.

## 1. Быстрый старт (локально)

```bash
npm install
cp .env.example .env.local   # можно оставить пустым — сайт запустится в демо-режиме
npm run dev                  # http://localhost:3000
```

**Демо-режим.** Пока переменные Supabase не заданы, сайт читает каталог и настройки из `src/lib/data/seed-data.ts`, а брони хранит в памяти процесса (пропадают при перезапуске). Так можно смотреть сайт и гонять тесты без базы. В демо-режиме админка недоступна, письма не уходят (печатаются в лог).

Требуется Node.js 22+.

## 2. Supabase: что сделать по шагам

У вас уже есть проект и два значения — **URL** и **Publishable key**. Нужен ещё третий ключ — **Secret key**: им сервер записывает брони и заявки.

**Шаг 1. Ключи.** Supabase Dashboard → *Project Settings → API Keys*:

| Что в Supabase | Куда вставить |
|---|---|
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` |
| Publishable key (`sb_publishable_…`) | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` |
| Secret key (`sb_secret_…`; нажмите *Create new secret key*, если его ещё нет) | `SUPABASE_SECRET_KEY` |

Локально — в файл `.env.local` в корне проекта (скопируйте `.env.example`); на Vercel — *Project → Settings → Environment Variables*; в Docker — см. раздел 4. Secret key нельзя показывать в браузере и коммитить в git. Старые названия `NEXT_PUBLIC_SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` тоже поддерживаются.

**Шаг 2. База.** Самый простой способ — без установки чего-либо:

1. Откройте в Supabase *SQL Editor → New query*.
2. Вставьте целиком содержимое файла `supabase/setup.sql` и нажмите *Run*.

Файл создаёт таблицы, права (RLS), хранилища для фото и заливает прайс, настройки и почтовые индексы. Запускается **один раз** на новом проекте.

Альтернатива для тех, кто пользуется CLI: `supabase link --project-ref <ref>` и `supabase db push --include-seed` (миграции в `supabase/migrations`, сиды в `supabase/seed.sql` и `supabase/seeds/postal_codes.sql`).

**Шаг 3. Администратор.** *Authentication → Users → Add user* (e-mail и пароль, галочка *Auto Confirm User*), затем в SQL Editor:

```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email = 'вы@example.com';
```

После этого открывайте `/admin`. Для входа по ссылке из письма добавьте `https://ваш-домен/admin/auth/callback` в *Authentication → URL Configuration → Redirect URLs*.

**Шаг 4. Проверка.** Перезапустите сайт. Плашка «демо-режим» на странице записи должна исчезнуть; сделайте тестовую бронь и найдите её в `/admin → Брони`.

Что важно знать о схеме:

- **Единый источник цен** — таблицы `services` / `service_options`. Прайс, лендинги, форма записи, JSON-LD, OG-картинки и письма читают цену оттуда; сервер пересчитывает сумму сам и не доверяет клиенту.
- **Двойная бронь невозможна**: на `bookings` стоит exclusion constraint по `(staff_id, tstzrange(starts_at, ends_at))` для активных статусов, запись идёт через функцию `book_slot()`.
- **RLS**: анонимам доступно только чтение активных услуг, настроек, галереи и опубликованных отзывов. Все записи делает сервер секретным ключом; админ — пользователь из таблицы `admins`.
- **Storage**: `gallery` (публичный, фото «до/после»), `quote-photos` (приватный, фото к B2B-запросу, до 30 шт.) и `booking-photos` (приватный, фото клиента к брони, до 6 шт.). В приватные бакеты браузер грузит по одноразовым подписанным ссылкам, админ смотрит по временным ссылкам.

Скрипты данных:

| Команда | Что делает |
|---|---|
| `npm run db:seed:generate` | пересобирает `supabase/seed.sql` из `src/lib/data/seed-data.ts` и `supabase/setup.sql` |
| `npm run db:bundle` | собирает `supabase/setup.sql` из миграций и сидов |
| `npm run db:postal-codes` | заново выгружает почтовые индексы (Statistics Finland, Paavo) |
| `npm run db:types` | `supabase gen types` → `src/lib/supabase/database.types.ts` |

## 3. Переменные окружения

См. `.env.example`. Кратко:

| Переменная | Зачем |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | канонический адрес (canonical, hreflang, sitemap, письма) |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` | база; секретный ключ — только на сервере |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` | ваш SMTP-сервер (почтовый ящик домена у хостера или регистратора). Порт 587 — STARTTLS, порт 465 — `SMTP_SECURE=true` |
| `MAIL_FROM`, `OWNER_EMAIL` | от кого уходят письма и куда приходят уведомления владельцу (по умолчанию — e-mail из настроек) |
| `NEXT_PUBLIC_GTM_ID` | Google Tag Manager (`GTM-PFGKLQJ5`): контейнер на всех публичных страницах и на 404; Consent Mode v2 выставляется до его загрузки |
| `NEXT_PUBLIC_GA_ID`, `NEXT_PUBLIC_GADS_ID`, `NEXT_PUBLIC_GADS_BOOKING_LABEL` | необязательно: GA4 / Google Ads напрямую через gtag.js, грузятся только после согласия. Если GA4 / Ads настроены внутри GTM — оставьте пустыми, иначе хиты задвоятся |

Письма: клиенту — подтверждение, перенос, отмена (на языке брони, со ссылкой на управление записью); владельцу — каждая новая бронь и заявка. Без `SMTP_HOST` письма только печатаются в лог сервера.

## 4. Деплой

### Vercel
1. Импортируйте репозиторий в Vercel (фреймворк определится сам, `vercel.json` не нужен).
2. Добавьте переменные окружения из раздела 3 для Production и Preview.
3. Подключите домен `puropesu.fi`. Адрес в `MAIL_FROM` должен принадлежать ящику, от имени которого разрешено отправлять ваш SMTP-сервер.

### VPS / Docker
```bash
docker build -t puropesu \
  --build-arg NEXT_PUBLIC_SITE_URL=https://puropesu.fi \
  --build-arg NEXT_PUBLIC_GTM_ID=GTM-PFGKLQJ5 \
  --build-arg NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co \
  --build-arg NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_... .
docker run -d --restart unless-stopped -p 3000:3000 --env-file .env.production puropesu
```
`NEXT_PUBLIC_*` вшиваются при сборке (build-arg), остальные ключи читаются при запуске из `--env-file`. Перед контейнером поставьте nginx / Caddy с HTTPS. Для rate limit прокси должен передавать реальный адрес клиента заголовком `X-Real-IP` (nginx: `proxy_set_header X-Real-IP $remote_addr;`) — значение `X-Forwarded-For`, присланное самим клиентом, не используется.

## 5. Как заменить контент

**Контакты и реквизиты** — `/admin → Настройки` (или таблица `settings`): телефон, WhatsApp, e-mail, Y-tunnus, адрес, соцсети. Нигде в коде они не захардкожены; футер, страница контактов, JSON-LD и письма берут их из настроек. До первого заполнения там стоят плейсхолдеры (`+358 40 000 0000`, `0000000-0`).

**Цены, длительности, активные категории** — `/admin → Услуги и цены`. Прайс взят из вашего документа «Puro — прайс и ценовая политика» (v3). Категории «Транспорт», «Лодки» и «Прочее» включены, потому что в документе у них есть цены Puro; выключите их галочкой «Активна», если на старте ими не занимаетесь — они исчезнут из прайса, записи, меню и sitemap, а страницы `/auton-verhoilupesu`, `/veneen-tekstiilit` начнут отдавать 404. Ковров, настенного текстиля и защитной пропитки в каталоге нет.

**Скидки и комплекты** — `/admin → Настройки → Скидки и комплекты`: проценты за первый и повторный заказ, за количество предметов, доплаты в комплектах «диван + стулья» и «диван + матрас», и переключатель «суммировать ли комплект со скидкой». Блок на главной, таблицы в прайсе и расчёт в записи берут числа оттуда.

**Фото «до / после»** — основной способ, когда подключён Supabase:

1. Снимите мебель до и после чистки с одного и того же места (тот же ракурс и кадр; горизонтально, лучше 4:3; JPG, PNG или WebP до 10 МБ).
2. Откройте `/admin → Галерея → Добавить пару`, выберите файл «до» и файл «после», раздел (диваны, кожа, стулья, матрасы…), подпись на финском (русская и английская — по желанию), оставьте галочку «Показывать на главной».
3. Нажмите «Добавить пару». Фото сразу появляются на сайте: в слайдере hero (первая пара), в 3D-кольце (первые 10 пар), в галерее на главной и на странице соответствующей услуги.
4. Порядок меняется полем «Порядок» (меньше — раньше). Демо-пары с пометкой DEMO удалите кнопкой «Удалить пару».
5. Чтобы поменять одно фото в уже добавленной паре, нажмите «Заменить» на самом снимке «до» или «после» и выберите файл: подпись, раздел и порядок остаются, старый файл удаляется.

Запасной способ (без админки): подмените файлы в `public/images/before-after/` с теми же именами (`01-kangassohva-before.jpg` / `-after.jpg` …) и пересоберите сайт.

**Логотип и иконки** — замените `public/brand/logo.png` (или `.svg`) и выполните `npm run icons`: пересоздадутся favicon, иконки приложения и OG-картинка по умолчанию.

**Отзывы** — `/admin → Отзывы`. На сайте и в `aggregateRating` участвуют только опубликованные; демо-отзывы — черновики.

**Тексты страниц** — `src/content/{fi,ru,en}/*.ts` (типы в `src/content/types.ts`); строки интерфейса — `messages/{fi,ru,en}.json`. В текстах нет цен и контактов: вместо них плейсхолдеры `{price}`, `{min}`, `{from}`, `{to}`, которые подставляются из базы.

**Блог** — MDX в `content/{fi,ru,en}/<id>.mdx`, слаги и даты — в `src/content/articles.ts`. В статьях доступны `<Callout>` и `<Price slug="sofa-3" />` (актуальная цена из базы).

**Города** — тексты в `src/content/{fi,ru,en}/cities.ts`, список — `CITY_MUNICIPALITY` в `src/content/index.ts`. Транспортный сбор для города считается из почтовых индексов и зон в настройках.

## 6. Как устроен проект

- **Страницы** (`src/app/(site)/[locale]`) — серверные компоненты, собираются статически и обновляются раз в 5 минут или сразу после правки в админке. Финский — без префикса, `/ru` и `/en` — с переведёнными адресами (таблица в `src/i18n/routing.ts`). Запросы распределяет `src/proxy.ts`.
- **Цены и настройки** читаются из базы в одном месте — `src/lib/data/public.ts`. Прайс, лендинги, главная, форма записи, JSON-LD, OG-картинки и письма берут значения оттуда, поэтому цена везде одна.
- **Расчёт заказа** — `src/lib/booking/cart.ts`: сумма, доплата до минимального заказа, комплекты, скидки, сертификат. Одна и та же функция считает живой итог в браузере и итог на сервере перед записью, клиенту сервер не доверяет.
- **Слоты** — `src/lib/booking/slots.ts` и `/api/availability`: окно работы и шаг из настроек, занятость из таблиц `bookings` и `blocked_times`, длительность визита = сумма позиций + буфер на дорогу.
- **Запись** — Server Action `src/app/actions/booking.ts`: проверка формы, лимит по IP, транспортный сбор по индексу, первый или повторный заказ (по e-mail и телефону прошлых броней), вызов функции `book_slot()` в базе. Ограничение в базе не даёт двум броням одного мастера пересечься. Если сумма на сервере отличается от той, что клиент видел при подтверждении (например, он оказался повторным клиентом или цену только что изменили), бронь не создаётся: клиенту показывается новая сумма, и он подтверждает ещё раз. Затем — ссылки для загрузки фото и письма.
- **Хранилище** — `src/lib/data/store*.ts`: реализация для Supabase и демо-реализация в памяти (когда ключей нет).
- **Формы** (контакты, B2B-запрос, сертификат, удаление данных) — `src/app/actions/forms.ts`.
- **Админка** — `src/app/admin`, вход через Supabase Auth, права проверяются и в коде, и политиками RLS в базе.
- **Тексты** — `src/content/{fi,ru,en}` (длинные тексты страниц), `messages/*.json` (интерфейс), `content/*/*.mdx` (блог).

## 7. Админка `/admin`

Вход по e-mail и паролю или по ссылке из письма; доступ только у пользователей из таблицы `admins`; раздел закрыт от индексации. Разделы: обзор, брони (список и календарь, смена статуса, звонок / WhatsApp, ручное создание), занятые дни (календарь: весь день или двухчасовой интервал закрывается и открывается одним нажатием; период и точные часы — формой), услуги и цены (правка и добавление услуг), галерея, B2B-запросы с фото, сообщения, сертификаты (статус «Оплачен» → код, PDF и письмо покупателю), отзывы, запросы на удаление данных, настройки и мастера.

## 8. Тесты и проверки

```bash
npm run lint          # ESLint
npm test              # Vitest: расчёт цены, скидки и комплекты, зоны, слоты + миграции/RLS/book_slot на встроенном Postgres (PGlite)
npm run test:e2e      # Playwright: запись от выбора позиций до подтверждения, гонка за слот, минималка, комплект, скидки, перенос/отмена
```

- `tests/db` прогоняет **настоящие** миграции и сид на PGlite и проверяет, что двойная бронь, чужие чтения и вызовы `book_slot` анонимом невозможны.
- e2e по умолчанию идут в демо-режиме. Чтобы прогнать их против базы, задайте переменные Supabase **тестового** проекта перед `npm run test:e2e`.
- Первый запуск e2e: `npx playwright install chromium`.

```
src/app/api/               слоты, транспортный сбор, .ics
src/app/actions/           Server Actions: бронь, формы
src/components/            UI: hero, слайдер до/после, мастер записи, формы, секции
src/content/               тексты страниц (fi/ru/en) и реестр статей

src/lib/data/              чтение каталога/настроек, хранилище броней (Supabase + демо)
content/                   статьи блога (MDX)
messages/                  строки интерфейса
supabase/                  миграции и сиды
scripts/                   иконки, плейсхолдеры, сиды
```

## 10. Перед запуском в прод — чек-лист владельца

- [ ] Заполнить настоящие контакты, Y-tunnus и адрес в `/admin → Настройки`; координаты базы для расчёта транспорта.
- [ ] Загрузить настоящие фото «до / после» (сейчас демо-иллюстрации).
- [ ] Прочитать и при необходимости поправить политику конфиденциальности (`src/content/*/privacy.ts`): сроки хранения и список сервисов должны соответствовать вашей практике.
- [ ] Проверить обещания в текстах: гарантия повторной чистки, письменное заключение для страховой по запросу, kotitalousvähennys — оставить только то, что вы действительно делаете.
- [ ] Решить открытые вопросы из прайс-документа: правила отмены и переноса, способы оплаты, обещаемое время высыхания (сейчас в текстах сказано только, что сушка бесплатная и ускоряет высыхание), суммируются ли комплекты со скидками (сейчас — нет, применяется то, что выгоднее клиенту; переключатель в настройках).
- [ ] Задать SMTP-настройки и отправить себе тестовую бронь, чтобы убедиться, что письма доходят.
- [ ] Добавить сайт в Google Search Console, отправить `https://puropesu.fi/sitemap.xml`; NAP в Google Business Profile должен совпадать с настройками сайта.
